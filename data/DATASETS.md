# Dataset inventory and pipeline requirements

Audit date: 2026-08-26

This file records the datasets required by the scripts in this repository, where each dataset should be placed, and whether it was present during the audit. Paths are relative to the repository root unless explicitly described as external.

## Status definitions

- **PRESENT**: the file is currently available at the expected repository location.
- **PUBLIC — DOWNLOAD REQUIRED**: the dataset is deposited in a public repository but is not stored locally at the expected pipeline location.
- **EXTERNAL — PRESENT**: the dataset is available locally outside this Git repository.
- **MISSING — BLOCKING**: a required input is absent, so the corresponding step cannot be reproduced.
- **NOT GENERATED**: an output from an earlier pipeline step is absent and blocks a later step.
- **OPTIONAL — MISSING**: the core step can run without the file, but an optional analysis or validation will be skipped.
- **EXTERNAL**: the input is expected outside the repository and its location must be supplied by the user.

## Required Space Ranger output files

For each sample, the loading scripts expect this minimum structure:

```text
data/raw/<sample_id>/outs/
├── filtered_feature_bc_matrix.h5
└── spatial/
    ├── tissue_hires_image.png
    ├── tissue_positions.csv
    └── scalefactors_json.json
```

`web_summary.html`, `cloupe.cloupe`, `raw_feature_bc_matrix.h5`, and the low-resolution image are useful archival outputs but are not read by the current R loaders. Zenodo 22058284 contains the web summaries and `.cloupe` files, but not the complete count-matrix and spatial `outs` folders. The STUtility loader may require the legacy `tissue_positions_list.csv` name when complete outputs use `tissue_positions.csv`. RNA velocity uses the 14 deposited loom files from `data/raw/loom/`.

## Code audit notes

- All 20 R scripts passed an R parser check.
- The RNA-velocity Python source passed a compile-only syntax check. It targets modern Python; the available fallback checker was Python 3.6, so the `from __future__ import annotations` declaration was omitted only in memory during this check.
- All four shell scripts passed `bash -n` syntax checks.
- Syntax checks do not confirm package installation, biological validity, or successful execution with full datasets.
- `02_spaceranger_count.sh` is a one-capture-area, argument-driven command with project-relative defaults. Run it once per intended capture area or wrap it with a project-specific sample sheet; the downstream canonical analysis uses 14 samples and excludes UL03 and DQ05.
- `04_map_scRNA_to_Visium_SPOTlight_Seurat_v5.R` now reads both organelle lists from their actual `data/reference/` locations.
- `scripts/R/03_add_metadata_seurat5/note.txt` refers to `scripts/R/03_add_metadata/`, but the actual folder is `scripts/R/03_add_metadata_seurat5/`.
- `data/processed/.RData` and `data/processed/.Rhistory` are RStudio workspace artifacts, not pipeline datasets; they should not be treated as reproducible inputs.

## Recommended order to resolve missing data

1. For reproduction from raw Visium reads, download PRJNA805024 and PRJNA804974, obtain the original histology TIFFs, and supply the reference, FASTQ, image, slide, and capture-area arguments to the Space Ranger count script.
2. Copy or link the external Space Ranger outputs into the documented `data/raw/<sample_id>/outs/` layout if the R loading steps will be rerun.
3. For rebuilding the scRNA reference, download SRR11943512 and SRR11943513 and generate the expected 10x-style count matrices.
4. Review the generated `SCINA_marker_table.csv`, especially the short `Leaf_rim` signature and the source-order top markers, then run the SAM–P5 Seurat/SPOTlight mapping workflow using the existing annotated reference.
5. Run the marker-analysis step to generate the currently absent marker tables.
